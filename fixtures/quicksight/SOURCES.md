## Search trail (negative results)

The following queries returned **no** real-world `.qs` bundles or full `describe-data-set` outputs with PhysicalTableMap+CustomSql+JoinInstruction on public GitHub:

- `"DescribeAnalysisDefinition" CalculatedFields filename:*.json`
- `quicksight analysis-definition.json` org:aws-samples
- `github quicksight "asset bundle" ".qs" example`
- `terraform-provider-aws quicksight_data_set acceptance test fixture PhysicalTableMap CustomSql`
- Inspected repos: `aws-samples/amazon-quicksight-assets-as-code-sample`, `aws-samples/amazon-quicksight-asset-migration-cicd`, `aws-samples/amazon-quicksight-sdk-proserve`, `WebCafeTech/quicksight-bundle-migration`, `yeahthisisrob/quicksight-asset-manager`, `aws-solutions-library-samples/guidance-for-multi-account-environment-on-amazon-quicksight`.

Conclusion: AWS does not publish reference fixtures for the full data-model surface area; the asset-bundle zip is treated as a private deployment artifact. The analysis-definition shape is well-covered by the assets-as-code sample; the dataset shape is best validated against the boto3 Stubber / AWS API reference rather than fixtures.
